# 操作手册：改参赛内容 → 发布自检 → 活动收尾

> 给"宣传/技术同学"看的 SOP。照着从上往下做，每一步都有验收标准。
> 适用：本机 / 学校服务器（`deploy/DEPLOY-SERVER.md`）/ Render（README 第 5 节）。

---

## 0. 三类改动，先分清

| 你要改的 | 改哪里 | 要不要重启服务 |
| --- | --- | --- |
| 作品名、阐述、序号、图片路径、增删作品 | `data/players.json` | **不用**（热加载，保存即生效） |
| 换作品图片 | `public/img/` 覆盖同名文件 | **不用**（刷新页面） |
| 截止时间、后台密码、公众号参数、端口 | 环境变量（`.env` 或 `/etc/campus-vote.env`） | **要**（`systemctl restart campus-vote`） |
| 页面标题、主办单位、配色、卡片布局 | `public/index.html`、`src/config.js` 默认值 | **要**（改代码） |

> Render 免费版不能直接改容器里的文件，**任何改动都要 `git push`** 触发重新部署。

---

## 1. 阶段一：准备素材（一次性，约 30 分钟）

**作品图片规范**

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 比例 | **4:3 横图** | 卡片固定 4:3 裁切，非 4:3 会被裁边 |
| 尺寸 | 宽 **1200px** 左右 | 太小糊，太大慢 |
| 体积 | **≤ 300KB** | 手机流量友好；用 Squoosh / 图压压 压缩 |
| 格式 | `.jpg` / `.png` / `.webp` | `.svg` 仅适合图标 |
| 命名 | `work-01.jpg`、`work-02.jpg`… | 只用英文数字，避免空格和中文 |

**作品文案**：每件 ≤ 200 字（超出会被服务端截断）；写清材料、技法、构思。

**清单核对**：件数、序号 1..N 连续、每件都有图和文、没有重名/重复 id。

---

## 2. 阶段二：改内容（每改一次约 3 分钟）

### 2.1 只换图片（最省事）

```bash
# 把新图直接覆盖旧文件名，JSON 完全不用动
copy new-01.jpg public\img\work-01.jpg
```

- 服务器上：`scp new-01.jpg vote@server:/var/www/campus-vote/public/img/work-01.jpg`
- 覆盖后浏览器 **Ctrl+F5** 强刷（Nginx 对 `/img/` 有 7 天缓存）

### 2.2 改文字 / 换图但改文件名 / 增删作品

编辑 `data/players.json`：

```json
[
  { "id": "p01", "no": 1, "name": "《红船启航》", "image": "/img/work-01.jpg", "desc": "以剪纸表现南湖红船……" },
  { "id": "p02", "no": 2, "name": "《星火》",     "image": "/img/work-02.jpg", "desc": "刺绣作品……" }
]
```

规则：

- `id`：唯一，**发布后不要改**（投票记录存的是它）
- `no`：卡片序号，页面按它升序；插队时把后面的序号顺延即可
- `name`：可留空（留空则卡片不显示标题行）
- `desc`：≤200 字
- 新增作品：追加一条，`id` 用没出现过的新值（如 `p07`）
- 删除作品：**先导出 CSV**，再删（历史票仍在库里，但不再计入合计）

改完保存：

```bash
# 检查 JSON 语法（可选，能提前发现少逗号）
node -e "JSON.parse(require('fs').readFileSync('data/players.json','utf8'));console.log('JSON OK')"
```

### 2.3 生效

- **服务器 / 本机**：保存 → 刷新页面即可。终端会打印 `[players] 已加载 N 个作品`
- **Render**：`git add . && git commit -m "update works" && git push` → 等状态变 **Live**（1–2 分钟）→ 强刷

## 3. 阶段三：发布与自检（5 分钟，必做）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 首页卡片数 = 参赛作品数 | 与报名名单一致 |
| 2 | 每张图都显示、主体没被裁掉 | 无裂图、无白块 |
| 3 | 序号 01、02… 连续且顺序正确 | 与公示名单一致 |
| 4 | 每段阐述完整（点「展开全文」） | 不被截断、没有乱码 |
| 5 | 手机 4G 打开 | 首屏 3 秒内出内容 |
| 6 | 后台「选手票数」有缩略图 | 说明图片路径都对 |
| 7 | 试投一次（用测试号） | 提示“明天可再投”，按钮变灰 |
| 8 | 截止时间显示正确 | 页面胶囊与倒计时一致 |

> 第 7 步试投会占掉一个身份当天的票额，正式开放前记得清库或用一个不影响统计的测试设备。
> 清库方法：停服 → 删 `data/votes.db*` → 重启（**只在活动开始前做**）。

---

## 4. 阶段四：活动中（每天 2 分钟）

1. 打开后台 `/admin`，看**总票数**是否异常暴涨、**同 IP 多条记录**里有没有明显机器人（同一 IP 几百票、UA 全是同一个）
2. 点一次「导出票数 CSV」存到群文件（命名 `票数_2026-11-21.csv`）
3. 有作品要补图 / 改错别字：按阶段二操作，不用停服
4. 每晚看一眼服务日志有没有报错：`journalctl -u campus-vote -n 50`

---

## 5. 阶段五：截止当天（关键 20 分钟）

| 时间 | 动作 |
| --- | --- |
| 23:30 | 导出**票数**与**明细**两份 CSV，作为“截止前快照” |
| 23:50 | 确认服务正常（`/healthz` = ok）、后台能进 |
| 24:00 | 系统自动关闭：页面显示「投票已于 11 月 24 日 24:00 截止」，按钮全部置灰，接口返回 403 |
| 00:05 | 再次导出**终版**两份 CSV（文件名带 `final`） |
| 00:10 | 在微信/群里发公告：投票已结束，感谢参与，X 月 X 日公示 |

**验证截止真的生效**（不要只看页面）：

```bash
curl -i -X POST https://vote.xxx.edu.cn/api/vote \
  -H "content-type: application/json" -d '{"playerId":"p01"}'
# 期望：HTTP/1.1 403 ... {"ok":false,"code":"CLOSED"}
```

> 截止时间由服务端判定，改前端 JS 无效，所以这一步基本不会出问题；但如果有人在 23:59:59 卡点，属于正常。

## 6. 阶段六：收尾与成绩折算

### 6.1 数据核对（在 Excel 里，5 分钟）

1. 打开「票数 CSV」：`各作品票数之和` 应等于 `合计`
2. 打开「明细 CSV」：行数 应等于 `合计`；`投票时间` 都在截止之前
3. 抽查异常：按 IP 排序，看同一 IP 是否异常集中；按身份标识看是否有大量 `ck:` 前缀（Cookie 身份，说明可能有人清缓存刷票）
4. 若确认要作废某些票：目前系统不做删除界面，两种处理
   - 会计层面：在 Excel 里直接扣除，并在备注里记录凭证（推荐，留痕清晰）
   - 数据层面：DBA 用 SQLite 删除 `votes` 表对应记录（需先备份）

### 6.2 70% 评审 + 30% 投票 折算

在「票数 CSV」后面加两列（假设票数在 `D` 列、评审百分制在 `E` 列）：

**投票分（比例法，推荐）**——第一名拿满 30 分，其余按票数比例：

```excel
=ROUND(30*D2/MAX($D$2:$D$7), 2)
```

**投票分（名次法）**——按排名递减（第 1 名 30，最后 1 名 30/N）：

```excel
=ROUND(30*(COUNT($D$2:$D$7)-RANK(D2,$D$2:$D$7)+1)/COUNT($D$2:$D$7), 2)
```

**总分**：

```excel
=ROUND(0.7*E2 + F2, 2)
```

> 两种算法差异：比例法下“第二名的票数如果只有第一名一半，分也只有一半”；名次法只看名次不看差距。
> 建议用**比例法**（更符合“按票数比例递减”的直觉），并在公示里写明算法。

### 6.3 公示与归档

1. 生成公示表：序号、作品名、票数、评审分、总分、名次（**不公开 IP、openid 等个人信息**）
2. 公示 3 天（11/25–11/27），期间保留后台但不对外
3. 归档：把「终版票数 CSV」「终版明细 CSV」「公示表」打成一个压缩包，命名 `2026红色手工大赛_投票数据.zip`，交学院存档
4. 活动结束后按学校要求处理个人信息：明细表（含 IP/openid）建议 **30 天后删除**，只留汇总；或按学院规定移交

### 6.4 站点下线（可选）

| 方式 | 做法 | 结果 |
| --- | --- | --- |
| 保留展示 | 什么都不做 | 页面继续展示作品，按钮置灰，不能再投 |
| 关闭站点 | Render 上 Suspend；服务器 `systemctl stop campus-vote` | 链接打不开 |
| 转到下一届 | 改 `EVENT_*`、`VOTE_DEADLINE`、`players.json`，清空数据库 | 复用同一套代码 |

---

## 7. 出问题怎么回滚

| 情况 | 处理 |
| --- | --- |
| 改 JSON 后页面没变化 | 强刷；看终端有没有 `[players] 已加载 N 个作品`；JSON 语法错会打印“解析失败，继续使用上一版” |
| 图片不显示 | 直接访问 `https://域名/img/work-01.jpg` 验证路径；检查大小写 |
| 改完代码报错 | `git checkout <上一个提交>` → 重启；服务器上 `git log --oneline -5` 找 |
| 数据误删 | 用最近的 `.backup` 文件（`/var/backups/campus-vote/`）或前一天的 CSV 重建 |
| 被刷票 | 后台导出明细 → 按 IP/UA 聚类 → Excel 扣除并留痕 → 必要时临时把 `IP_LIMIT_MAX` 调低重启 |
